# Случайные числа 🎲

Android-приложение для генерации случайных значений с сохранением «сессий»
генерации: задайте параметры, при необходимости включите режим «без
повторений» — и получайте значения, которые не повторяются, пока весь
диапазон не будет исчерпан. Поддерживаются числа в диапазоне, случайный
элемент из списка, кубики, монета и перемешивание списка.

## Возможности

### Режимы генерации

- **Числа** — случайное число в заданном диапазоне `от…до`; «без повторений»
  гарантирует, что уже выданные числа не появятся снова до исчерпания.
- **Список** — случайный элемент из введённого пользователем списка (пустые
  строки и дубликаты отбрасываются; «без повторений» работает так же).
- **Кубики** — бросок набора `NdM` (например, `2d6`); крупно показывается
  сумма, ниже — детализация «4 + 2 + 6». Броски всегда повторяемы.
- **Монета** — «орёл/решка» с подсчётом исходов; броски всегда повторяемы.
- **Перемешивание** — новая случайная перестановка всех элементов списка
  за одно нажатие (тасование Фишера–Йетса).
- У каждого режима общий каркас экрана (журнал, экспорт, seed), а перед
  формой открывается экран выбора режима.

### Генерация

- **Батч-генерация** — за одно нажатие 1/2/3/5/10 значений; в режиме
  «без повторений» значения в батче уникальны, при частичном исчерпании
  выдаются оставшиеся.
- **Пресеты диапазонов** — «Кубик 1–6», «Монета 0–1», «Лотерея 1–45»,
  «Сотня 1–100» заполняют форму одним тапом.
- **Ручное редактирование истории** — добавление числа вручную (с валидацией
  диапазона и повторов), удаление отдельного значения, отмена последнего.
- **Seed (воспроизводимость)** — зафиксированный seed даёт одну и ту же
  последовательность: розыгрыш можно проверить повторным прогоном. Seed
  имеет приоритет над выбором источника случайности.
- **Честный розыгрыш** — один тап на главном экране: seed выбирается
  криптографическим источником (`SecureRandom`) и сохраняется, результат
  сразу уходит в share-sheet вместе с seed и источником — итог можно
  проверить. Доступны розыгрыш числа 1–100 и розыгрыш участника из списка.
- **Источник случайности** — обычный ГПСЧ Kotlin. В домене есть адаптер
  `SecureRandom` (`RandomSourceMode.SECURE`) с корректной обработкой широких
  диапазонов; в UI отдельный переключатель источника пока не выведен —
  криптографический источник используется для seed «честного розыгрыша».

### Сессии

- **Список сессий** — продолжить, удалить (с подтверждением), поиск по
  названию/тегам, фильтры «Все / Избранное / Архив» и сортировка
  (по дате, названию, прогрессу).
- **Теги и избранное** — свои теги на карточке (тап → поиск) и звёздочка
  избранного; архивные сессии скрыты из общего списка.
- **Диалог «Все числа выбраны!»** — когда в режиме «без повторений» выбран
  весь диапазон: создать новую сессию или сбросить текущую.
- **Статистика сессии** — количество, уникальные, повторы, мин/макс, среднее,
  медиана, самое частое/редкое значение.
- **Дублирование сессии** — долгое нажатие на карточку → «Дублировать»: копия
  с теми же настройками и пустой историей.
- **Журнал с таймстампами** — каждое значение хранится с временем выдачи
  (старые данные мигрируют автоматически).
- **Виджет «Последняя сессия»** — показывает последнее значение и умеет
  сгенерировать следующее прямо с домашнего экрана (Glance).
- **Плитка быстрых настроек «Сгенерировать»** — один шаг в последней сессии
  без открытия приложения; общая логика с виджетом.
- **Ярлыки рабочего стола** — долгий тап по иконке: «Новая сессия» или
  «Последняя сессия».

### Экспорт и импорт

- **Экспорт истории** — CSV (с таймстампами), TXT (список), JSON (сессия
  целиком), Markdown (таблица с временем); сохранение в файл через системный
  диалог (`ACTION_CREATE_DOCUMENT`) или отправка через share-sheet.
- **Перенос всех сессий** — версионированный JSON-файл: экспорт на одном
  устройстве, импорт на другом. Повреждённый JSON или файл с несовместимой
  версией не применяется — импорт завершается сообщением об ошибке и не
  «съедает» данные.

### Персонализация

- **Тема** — системная/светлая/тёмная, акцентный цвет (динамический Android 12+,
  индиго, бирюза, роза).
- **Отклик при генерации** — вибрация и/или короткий звук; опционально сигнал
  на каждое значение батча.
- **Локализация** — русский и английский (все строки в ресурсах, включая
  заголовки сессий, стороны монеты и служебные строки шаринга/экспорта;
  заголовки вычисляются при показе, поэтому язык применяется и к старым сессиям).

### Ключевая логика: режим «без повторений»

`NumberGenerator.next(...)` возвращает `GenerationResult.Success(number)` либо
`GenerationResult.Exhausted`, когда все числа диапазона выбраны. Для больших
диапазонов используется комбинированная стратегия: 128 быстрых «бросков»,
затем выбор свободного значения обходом по кругу от случайного сдвига —
сложность не зависит от размера диапазона (для 1..10 000 000 это миллисекунды).

`Session` хранит журнал `log: List<GeneratedEntry(value, at)>` и вычисляет
`pickedCount` / `isExhausted`; `SessionViewModel.generate()` добавляет батч,
сохраняет сессию и показывает диалог исчерпания, если значения кончились.

### Режимы и журнал

Все режимы разделяют одну модель `Session`: параметры вынесены в sealed-тип
`SessionPayload` (`data/SessionPayload.kt`), а журнал остаётся списком `Int`.
Для чисел это сами значения, для списка/перемешивания — индексы элементов,
для кубиков — значения кубиков, для монеты — `0`/`1` (`CoinSide.ordinal`).
Один `SessionGenerator` (домен) выполняет «один шаг» для любой сессии — его
используют и `SessionViewModel`, и виджет с плиткой, поэтому поведение
одинаково. Новый режим добавляется подтипом `SessionPayload` с `@SerialName`;
старые сессии читаются как `Numbers`.

### Устойчивость хранилища

- каждая сессия лежит отдельным ключом (`session_<id>`), запись одной сессии
  не переписывает остальные;
- повреждённая запись пропускается при чтении, логируется и **не затирается**
  следующей записью;
- данные старого формата (одна JSON-строка) переносятся автоматически;
- операции над состоянием сессии выполняются последовательно в одной очереди:
  быстрые повторные нажатия не теряют значения;
- удалённая сессия не «воскресает» повторным сохранением.
